# Folder KB 评测入口

评测分三层，各层回答不同问题，不能用工具成功率替代任务成功率，也不能用 Agent 的多轮累计召回代替单次检索质量。

| 层次 | 输入与执行 | 衡量什么 | 入口 |
|---|---|---|---|
| Agent 任务 | 自然语言目标 + 独立知识库；OMP 自主选择 MCP 工具 | 目标达成、事实与引用、写入副作用、调用和时间成本 | [基础读写](agent/README.md)、[BrowseComp-Plus](browsecomp/README.md)、[平台业务](workflows/README.md) |
| 固定查询 | 固定查询 CSV + 相关文档标签；每题调用一次 Search | Recall@K、nDCG@K、MRR、Precision、索引构建与查询时间 | [检索评测](retrieval/README.md) |
| 并发负载 | 合成语料 + 多客户端，对独立 HTTP 进程施压 | 成功率、吞吐、成功请求 P95、错误类别 | [负载评测](load/README.md) |

## 当前范围

- 基础读写：12 个任务，对比 grep / search / hybrid，各任务可重复三次；含查证、跨文档综合、无答案拒绝、创建、修改、清理和移动。
- 公开问答：BrowseComp-Plus 数据适配、证据追踪、离线判分与上游格式导出。当前基线为 20 题、304 篇文档，不能与官方全量榜单比较。
- 平台业务：6 个阶段，覆盖多库不同权限、未授权库拒绝、写后索引失效与手动重建、提交—候选—审核—发布—再次读取。
- 固定查询：8 项合成检索用例；也可从既有公开基准的固定轮次冻结首次查询，使用相同查询文件比较插件。
- 负载：read / search / mixed / background 四种场景；客户端数、请求数和合成库规模可配置。

知识文件、任务 CSV、验收 JSON 分离存放于 `datasets/`。平台业务任务有前后依赖，每轮重置；基础读写每次任务、配置、重复均重置。标准答案不挂载给 Agent。当前默认模型是本机 OMP 已配置的 GLM-5.3-Flash。

## 建议执行顺序

1. 模型预检，然后少量基础任务确认工具接入。
2. 固定模型、语料、插件、预算与平台源码，执行三种工具配置的重复基线。
3. 用固定查询比较索引插件，再用 Agent 任务验证这种变化是否改善最终完成效果。
4. 运行平台业务场景，验证权限与更新流程。
5. 单独运行负载测试。不要与模型评测或其他负载并行，避免干扰耗时结果。

每次使用新的输出目录。保留失败、超时和旧报告；重评分不覆盖原始结果。新 runner 会保存源码快照及语料、插件指纹；需要严格冻结执行时，应从选定提交的独立检出运行，避免测量中途编辑源码。

均启动随机本地端口的隔离平台，无生产 URL 参数。新数据只来自合成测试库或明确导入的公开语料，不访问个人库。运行记录、题目、答案和工具轨迹放在 Git 忽略的 `data/`，仓库只保存源码、合成测试数据与脱敏汇总。

最新结果见 [2026-10-13 扩展报告](../docs/reports/2026-10-13-benchmark-expansion.md)；历史基线的评分复核见 [复核报告](../docs/reports/2026-10-13-benchmark-review.md)。

BrowseComp-Plus 已作为检索主基准提供 [campaign 入口](browsecomp/README.md)：配置式插件矩阵、无知识库对照、问题生成的固定查询、配对增益与按题目重采样区间、人工抽检导出和复核。只生成计划与实际执行分开，默认主矩阵每题四组各重复三次；当前仍是有明确容量边界的缩小语料评测。
