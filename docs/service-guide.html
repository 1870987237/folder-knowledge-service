当前实现：Python / FastAPI / MCP / SQLite · 文档更新：2026-09-18

以文件夹和文档保存知识，通过 MCP 与 REST 为 Agent 提供只读搜索和阅读能力。

1. 实现方式

1.1 Agent 如何访问知识

1.2 服务端如何实现

在 Linux 上部署 Python 服务（FastAPI + MCP Python SDK），只读挂载知识目录。Agent 通过 MCP 或 REST 调用文件工具，服务直接搜索和读取文件，不建立向量索引、不调用大模型。

搜索与读取
glob 匹配文件路径，grep 搜索文本，read_file 按行读取；大文件按块扫描，返回结果受预算限制，支持游标续读。
存储与更新
知识保留在原始文件夹；目录映射、Key 哈希、授权和访问记录存入 SQLite。修改知识文件后，后续请求即可读取新内容。
格式与权限
支持 UTF-8 文本文件；PDF、Word 和图片需先转换为文本。Agent 只能访问已授权目录，不能写入、删除或执行文件。

2. 工具能力

MCP 工具用途对应 REST 路径
list_libraries查看获授权且启用的知识库及目录可用性/api/v1/libraries
knowledge_info了解支持格式、查询限制和工具使用方式/api/v1/info
list_directory浏览一层目录，支持分页/api/v1/list
glob按文件路径查找，例如 **/*.md/api/v1/glob
grep字面或有界正则搜索，返回行列位置与上下文/api/v1/grep
read_file按行读取原文，支持大文件和超长行续读/api/v1/read

常用过程：发现知识库，浏览或搜索资料，读取上下文，再引用原文回答。MCP 与 REST 使用相同的知识访问实现和参数名。

4. Agent 接入

将下面的指令交给要接入的 Agent。由它识别客户端、写入配置并验证工具调用。前提是服务已部署，管理员已发放具有知识库访问权限的 Agent Key。

发给 Agent 的配置指令
请为你当前使用的客户端配置文件夹知识服务，并完成真实连接验证。请直接执行可完成的配置，不要只返回操作教程。

连接信息：
- 服务名称：folder-knowledge
- 服务根地址：http://192.168.18.116:8791
- MCP 地址：http://192.168.18.116:8791/mcp
- 传输协议：Streamable HTTP
- 认证请求头：Authorization: Bearer <Agent Key>
- 密钥环境变量：KB_AGENT_KEY；这是 Agent Key，不是管理员令牌。

请完成以下工作：
1. 检查当前客户端、操作系统和已有 MCP 配置，确认其支持 Streamable HTTP 与 Bearer 认证。根据客户端本地帮助或官方配置说明确定配置位置和格式，不猜测配置字段。已有同名条目时检查并更新，保留其他服务配置。
2. 优先引用客户端现有密钥存储或 KB_AGENT_KEY，只检查密钥是否可用，不输出原文。若缺失，向我索取安全录入方式或请我在客户端密钥输入界面补充，然后继续。不要把 Key 写入提示词、日志或仓库文件。
3. 使用客户端支持的方式保存 MCP 配置。若是 Codex CLI，先核对 codex mcp add --help；支持对应参数时使用：
   codex mcp add folder-knowledge --url http://192.168.18.116:8791/mcp --bearer-token-env-var KB_AGENT_KEY
   确认运行客户端的进程能够读取该变量。其他客户端使用各自的配置格式，不直接套用 Codex 命令。
4. 配置后尝试重新加载 MCP 并完成协议初始化、工具发现。若必须由我重启客户端或当前会话无法加载新工具，说明已经完成的部分和唯一需要我做的动作，不把“配置已写入”当作“连接成功”。
5. 通过 MCP 调用 list_libraries，发现真实可访问的知识库，不使用示例 ID。只有一个库时自动选择；存在多个库且我未指定目标时，列出名称与 ID 让我选择。随后调用 knowledge_info、list_directory，并选择一个实际存在的文本文件，用 read_file 读取前 30 行；后续调用显式传入 library_id。若为空库或目录不可用，如实报告，不编造读取结果。
6. 汇报配置位置、实际连接状态、可用工具和本次读取的知识库 ID、文件路径与行号，不展示 Key。若失败，依据网络、认证、授权、目录和参数定位原因，报告尚未完成的验证。

如果客户端不支持远程 MCP，说明具体限制；可用同一 Key 通过 REST 验证服务可达性，但必须区分 REST 可用与 MCP 已连接。不要为了接入而重新部署或修改服务端配置。

5. 后续改进方向

以下为计划方向，尚未实现。

5.1 增量记录知识改进建议，支持 KB 持续演进

服务端新增反馈命令，并通过 MCP / REST 暴露给 Agent。当用户提出与知识库不同的意见，或 ArcGen 实际使用结果与文档不一致时，Agent 可记录发现的问题和改进建议。

  • 记录内容：关联知识库、文件路径与版本，原有表述、实际场景、用户意见或验证证据、建议修订内容，以及来源和时间。
  • 保存方式：在 Folder KB 的独立反馈目录中追加记录，例如一条反馈一个 JSON / Markdown 文件；保留历史，不覆盖正式知识。
  • 沉淀方式：定期汇总、去重和验证反馈，将确认有效的建议合入知识文档，保留修改依据与版本。

用户意见先作为待验证反馈；反馈提交使用单独权限，现有知识读取接口继续保持只读。

发现差异 → 追加反馈记录 → 汇总与验证 → 更新知识文档 → 后续 Agent 使用

5.2 Rust 重写与受保护的打包交付

将服务端改为 Rust 实现，保持现有 MCP / REST 接口，探索服务程序与知识库的一体化交付。

方向拟实现方式
服务程序保护以编译后的 Rust 二进制交付，减少直接分发源码；代码保护与防篡改方案另行设计。
知识库加密对知识文件或知识包进行加密存储，运行时由获授权的服务解密读取，密钥与交付包分离管理。
整体打包以 Docker 等方式统一交付服务程序和加密知识包，并设计版本、升级与回滚机制；可变反馈记录单独持久化。

技术边界：Rust 编译和 Docker 打包本身不等于加密，也无法保证在掌握宿主机权限的环境中隐藏运行时明文。需先明确保护对象、部署环境和密钥管理方式，再确定整体保护方案。

5.3 基于 sanza-wasm 与 Folder KB 的网页版 Training Agent

新增网页版 Training Agent，结合 sanza-wasm 与 Folder KB，提供围绕知识库开展交互和训练任务的统一入口。

  • 知识接入：按用户或 Agent 授权访问 Folder KB，支持搜索、阅读和引用知识。
  • 经验回流：对交互中发现的知识差异，调用增量反馈命令，进入验证和知识更新流程。
  • 待细化：sanza-wasm 的执行职责、浏览器与服务端分工，以及训练任务、轨迹记录和结果验收方式。

附录 A. 调用示例与续读方式

REST：先列库，再搜索和读取

以下示例供 Agent 调用时参考，假定其进程已获得 KB_AGENT_KEY。知识库 ID、读取路径和行号应从实际结果取得。

REST · 列出知识库与搜索
export KB_URL='http://192.168.18.116:8791'

curl -fsS -H "Authorization: Bearer $KB_AGENT_KEY" \
  "$KB_URL/api/v1/libraries"

curl -fsS -G -H "Authorization: Bearer $KB_AGENT_KEY" \
  --data-urlencode 'library_id=team-guide' \
  --data-urlencode 'query=备份' \
  --data-urlencode 'file_glob=**/*.md' \
  --data-urlencode 'context=2' \
  "$KB_URL/api/v1/grep"
REST · 读取指定行
# 将 README.md 和行号替换为实际搜索结果
curl -fsS -G -H "Authorization: Bearer $KB_AGENT_KEY" \
  --data-urlencode 'library_id=team-guide' \
  --data-urlencode 'path=README.md' \
  --data-urlencode 'start_line=1' \
  --data-urlencode 'end_line=30' \
  "$KB_URL/api/v1/read"

MCP：工具参数示例

这是工具调用参数示意，不是向 /mcp 直接 POST 的协议报文。MCP 客户端负责初始化与工具调用协议。

read_file · 首次读取与续读
{
  "library_id": "team-guide",
  "path": "records.jsonl",
  "start_line": 1,
  "end_line": 20
}

{
  "library_id": "team-guide",
  "path": "records.jsonl",
  "cursor": "上一次返回的 next_cursor"
}
  • 将 next_cursor 传回 cursor 继续读取，超长行可能从同一行的后续列开始。
  • 搜索续查保留原查询条件，传入 cursor 并保持 offset=0。
  • 可将搜索结果的 version 传给读取请求的 expected_version，检查文件是否发生变化。
  • version 基于文件元数据，用于常规更新检测，不是内容哈希。文件变化或服务重启后，需重新开始查询。
  • partial=true 表示结果不完整。目录遍历未覆盖的范围或跳过项不能靠当前游标补齐，需要缩小查询范围并检查原因。

附录 B. 管理员部署与日常维护

部署在 Linux 服务器，使用 Docker Compose。配置 KB_SOURCE_DIR 指向真实知识目录池，Compose 将它映射为容器内的 /knowledge。

Linux · 从项目根目录部署
cp .env.example .env
chmod 600 .env
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'

# 将生成的随机值填入 .env 的 KB_ADMIN_TOKEN
# 配置 KB_SOURCE_DIR、KB_ALLOWED_HOSTS、KB_BIND_IP、KB_PORT
docker compose up -d --build
docker compose ps
配置用途
KB_SOURCE_DIR服务器真实知识目录，例如 /srv/knowledge。知识内容只读挂载。
KB_ADMIN_TOKEN管理台令牌，至少 24 字符。与页面生成的 Agent Key 分开使用。
KB_ALLOWED_HOSTS实际访问域名或 IP，含端口形式，例如 kb.example.com 或 10.0.0.8:*。
KB_BIND_IP / KB_PORT默认 127.0.0.1:8790，供同机反向代理。内网直连时绑定服务器内网 IP。

推荐使用 HTTPS 反向代理，保留 Host 和 Authorization 请求头。容器以 UID/GID 10001:10001 运行，宿主机需要允许其读取文件和遍历目录。

动态目录与权限

挂载范围内新增目录，可直接注册为知识库。超出范围时需要调整挂载并重建容器。目录映射、启停与 Key 授权变更对后续请求生效，正在执行的请求可以完成。

目录被删除或不可读时，服务报告原因并保留配置与授权。原目录恢复后，后续请求可继续访问。

持久化与备份

/service-data/management.sqlite3 保存配置、Key 哈希和访问审计。保留独立数据卷，知识文件另行备份。使用 SQLite Backup API 备份运行中的数据库。

当前为单实例、单 worker，管理数据卷使用服务器本地磁盘。访问活动按 Key 统计，共用 Key 的客户端记录会合并。

查询预算

大文件不会因超过 2 MiB 直接被拒绝。服务按块读取，单次文本扫描最多 32 MiB，目录遍历与读取/搜索分别有 5 秒预算。每次读取最多 500 行范围、500 个行片段和 48,000 个正文字符，达到限制时通过游标继续。

截至 2026-09-17：本地后端测试 58 项通过、2 项因平台条件跳过，实测 9.6 MB 超长行文件可续读。目标 Linux 服务器的容器、权限与网络验收仍待完成。

附录 C. 连接问题排查

现象检查方式
连接超时或拒绝连接检查地址、端口、服务器绑定 IP、防火墙和代理。远程机器不能用 127.0.0.1 访问服务器上的服务。
401 unauthorized使用 Agent Key，检查 Bearer 前缀、环境变量，以及 Key 是否过期或撤销。Admin Token 不能代替它。
421 invalid_host将实际域名或带端口的 IP 加入 KB_ALLOWED_HOSTS，检查反向代理是否保留预期 Host。
403 library_forbidden检查该 Key 的知识库授权，以及目标知识库是否启用。
library_required先调用 list_libraries，再明确传入 library_id。该错误也可能表示当前没有可用授权库。
列库结果为空管理员先注册并启用知识库，再给当前 Key 授权。查看是否误用了另一枚 Key。
503 library_unavailable检查目录存在性、类型和读取/遍历权限。按返回的 reason 修复目录后重试。
version_changed / invalid_cursor文件变化、服务重启或查询条件不一致时，放弃旧游标，从首次查询重新开始。
403 invalid_origin不要把此离线教程页当作跨站 API 客户端。使用支持的 MCP 客户端或终端请求，并按部署策略配置来源。
工具参数不包含 cursor服务更新后，重连 MCP 并刷新工具定义。

排查顺序建议为：网络地址、认证、知识库授权、目录可用性、查询参数。页面能打开只说明管理页面可达，仍需使用 Agent Key 验证一次真实工具调用。
