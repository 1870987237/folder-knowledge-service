# 基础插件真实模型测试报告 · 2026-10-16

结论：修复后，通用知识库完成 10/10 个候选处理与审核发布阶段，实际 MCP 验证 13/13 项通过。发现并修复系统代理连接、非纠错材料被模型建议覆盖、元数据污染检索三个问题。这是小型功能验收，不代表大规模检索或通用语义准确率。

## 测试环境与边界

- 模型：已配置的 hyper-op/GLM-5.3-Flash，真实 Chat Completions 调用。
- 独立合成工作区，最终 3 篇知识文档＋总目录。没有读取用户私有知识库。
- 更新程序由真实平台 worker 子进程运行；测试执行器记录诊断输出，使用真实模型请求的本地统计转发，不模拟模型决策。测试脚本为合成候选执行审核操作，生产仍须人工审核。
- 精确去重、重放、输入不变、权限隔离由程序断言；8 个行为断言通过。另检查生成正文：Atlas 超时 45 秒、最多重试 2 次、间隔 5 秒；Boreal 超时 90 秒，来源分别记录。未使用另一个模型自动判分。

所有阶段发布前正式知识保持不变。冲突与观察发布的是待审记录，正文未改；“published”不等于这些材料成为已确认知识。首条提交再以相同 submission_id 重放，收件箱返回 duplicate，新增模型调用为 0。

最终完整轮共 7 次模型调用，接口成功 7/7，合计 12,054 tokens（仅此轮）；包含索引与检索的完整轮耗时 146.06 秒。单次模型相关候选耗时约 10–42 秒，精确重复约 1.23 秒。不能据此推算大型知识库、并发或长期运行的耗时。

## 检索和真实 MCP

- 修复前，“Atlas 超时”首条为总目录；来源 frontmatter 可携带已纠正的旧参数，造成冗余片段。
- 修复后，两个插件跳过可识别的文首来源元数据块，保留正文原始行号。通用插件另排除自动生成的 INDEX.md，独立 BM25 插件保留索引用户现有 INDEX.md 的行为。
- 用同一份已生成的资料复测，通用插件的 Atlas 超时、Boreal 超时、HTTPS 三条查询首条均为对应正文；无答案查询返回空。两插件共 8 次直接检索成功，8/8 返回片段不含原始来源元数据。
- 通用库手动建索引 0.674 秒（3 文件）；独立 BM25 0.757 秒（4 文件）。数据很小，不能与全量 BrowseComp 性能直接比较。
- 真正 MCP Streamable HTTP：工具发现 1 项、Search 6 次、证据读取 4 次、越界 metadata 读取拒绝 1 次、未授权库检索拒绝 1 次，共 13/13 检查通过。正常调用成功，两个拒绝是预期结果。
- MCP Search 六次的耗时中位数 0.713 秒，范围 0.611–0.752 秒，包含协议、平台校验和插件运行。

BM25 仍采用 OR 词法召回：同库内较低排名可出现其他项目的相似文本。scope 是内容组织字段，不是访问隔离。真实权限隔离仍按知识库及 Key 配置。

## 失败记录与修复

1. r1：初始化成功，首次新增失败；3 次上游 HTTP 请求失败。单独探测默认系统代理返回 502，而直接连接和 OMP 都成功。1.0.1 增加 use_system_proxy，默认 false；需要代理时显式启用。
2. r2：新增、精确重复、同义重复、补充合并通过；冲突任务失败。独立诊断复现模型对 new_content 提出 revise，现有校验拒绝执行。r2 未留存原始模型正文，诊断结果不冒充该次原始响应。修复为：通过结构、目标范围与引文校验后，将非 correction 的 revise 转待审；并加强材料类型提示。
3. r3：完整更新轮通过。随后发现检索片段含审计来源；修复分块后，使用同一份冻结合成资料进行独立检索与 MCP 复测，没有重新生成答案挑选更好结果。

早期失败没有算入最终修复版的成功率，也没有删除。未宣称模型不会漏判冲突；非法输出仍可能导致明确失败，模型整理仍需审核。
