# Benchmark 基线复核与扩展

## 怎样测

知识目录、自然语言任务 CSV、验收规则分别保存。OMP 只获得任务、平台实际 MCP instructions 和工具 schema；不获得答案，也不能使用本地文件、Shell 或外部搜索。薄适配层仅注册并转发真实 MCP HTTP 工具，不规定调用顺序。每个任务重新创建隔离库、Key 和会话。

grep / search / hybrid 保持语料、模型、预算一致，按任务轮换顺序，各重复三次。执行后检查事实、引用、最终文件和无关副作用，保留错误、超时及完整轨迹。BrowseComp 使用独立无工具会话判分，但目前判分模型与被测模型相同，仍须人工抽检。

## 失败复核

- 6 次写任务只增加了段落空行：W02 五次，W03 一次。目标字段均正确，无关文件未改。精确文件约束仍不通过，但不应标为“目标没有执行”的虚报。评分器 1.3 新增保守的 `formatting_only_failures` 诊断；代码块、列表、缩进等不做此归类。严格成绩不放宽。
- R02-grep-3 回答含正确事实和来源，但 JSON 字符串里有未转义换行。保留结构错误及原失败分数，不自动修补 Agent 输出。
- 4 次 R05 正确拒绝没有依据的奖金问题，却填 `completed=true`。属于状态协议不一致。
- 读写 11 次工具错误中，9 次在恢复后严格完成任务。接口错误本身不能证明工具误导；创建前探测不存在文件是正常探索。
- 公开问答 6 次执行失败的退出码均为 1，耗时约 180 秒，服务端工具均没有报错，符合任务预算耗尽特征；不归为服务器故障。另有 3 个答案被同模型判错，尚需独立判分或人工逐题复核。
- 公开问答 426 次 Search 中，83 次没有新增文档，192 次没有新增标准证据，没有完全相同参数的重复查询。零新增不自动视为无效；需要结合补充片段和确认行为解释。

全部 108 次保存记录已统一离线重评分，没有重新执行模型。原始 `results.json` 保留，修订结果为 `data/baseline-20261012/readwrite/graded-results.json`，报告为 `reviewed-report.md`。总体仍是目标达成 101/108、严格通过 97/108；虚报标签由 6 修正为 0，不能据此声称通过了完整幻觉检测。

重评分使用冻结源码内的数据目录。Windows 工作区 CSV 的嵌入换行与 Git archive 的换行形式不同，导致任务指纹不一致；校验拒绝混用，未跳过数据一致性检查。

## 后续顺序

1. 已完成基线复核和评分分类修正。
2. 独立检索：固定查询及 K，文档去重后计算 Recall@K、nDCG@K，明确片段上限和超长查询处理，不静默截断。
3. 业务任务：多库授权、写后索引失效与手动重建、材料提交到人工审核发布。Agent 自主完成其权限内任务；平台人员的审核由独立测试角色执行。
4. 并发负载：独立合成库，分开统计只读、Search、混合写入和后台更新负载；不将接口压测称为 Agent benchmark。

原始题目、答案和轨迹保留在被忽略的本地目录；仓库只提交代码、合成数据和脱敏汇总。
