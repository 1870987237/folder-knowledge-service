# BrowseComp-Plus 主基准建设

本轮将 BrowseComp-Plus 从单次实验入口补为配置式主基准，保持“自然语言任务、通用 Agent 自主选工具、独立验收”的边界。默认答题和判分均使用 OMP 已配置的 GLM-5.3-Flash；按照用户选择保留同模型偏差提示，不把它称为独立模型判分。

## 已实现

| 能力 | 说明 |
|---|---|
| 数据冻结与开发集排除 | 原始题目不改写；随机抽取题目、排除已经用于开发的任务；保留全部 evidence/gold 与固定困难负例；记录原分片、种子和指纹 |
| 无知识库对照 | 同模型、同问题、同预算，禁用全部工具；记录真实模型请求工具目录，确认没有文件、Shell、外部检索或 MCP |
| 配置式工具与插件矩阵 | 一个配置文件定义模型、预算、重复次数和多个插件；各插件可选择 grep/search/hybrid；控制组只跑一次 |
| 固定查询实验 | 只根据问题生成短查询，在检索前冻结，所有插件共用；独立报告 Recall@K、nDCG@K、MRR、Precision |
| 配对效果报告 | 按题目和重复编号比较接入知识库前后的确认正确率增益、调用数、耗时与 Token；按题目聚合后 bootstrap，避免把重复任务当成独立题 |
| 人工抽检 | 导出全部有效错例/未判答复及各组随机正例，隐藏组别和机器评分；回填时校验原内容、审核人和理由，保留原始机器分数 |
| 可追溯执行 | 源码、数据、插件与任务矩阵指纹；分阶段状态；保留失败与旧目录；已完成阶段可校验哈希后跳过 |

查询准备最多允许三次格式/长度尝试，记录每次结果；不看检索成绩挑查询，不用答案补关键词。Agent 正式答题不采用这种自动修复或选择性重跑。进程失败、超时、未判与答错分别记录。

## 冻结数据与正式计划

新数据在本地 `data/bcp-main-50-20261013/`：

- 50 道题，从已缓存的官方第一分片 139 题中按 seed=20261013 抽样。
- 排除旧开发集 20 道题，新旧任务 ID 不重叠；这不表示模型训练时没有见过这些公开题。
- 每题保留全部 evidence/gold，另抽 3 篇困难负例；所有题共用 471 篇完整文档。
- 11,048,165 字节，11,082 个 Markdown 分块；未截断正文或丢掉标准证据。
- 语料 SHA256：`0d114cf658869df308b40f4b18d6138a276e6f00916ae64f7a0de8fa3f0d3d50`。

容量预检曾检查每题 10 篇和 5 篇负例，均超出演示索引 16 MiB/16,000 分块上限。最终在任何正式模型答题前冻结为 3 篇。新旧数据难度不同，不能用两轮分数之差宣称算法改进；后续插件必须在同一冻结集上比较。

`benchmarks/browsecomp/configs/main.json` 默认计划：

- 无知识库 + 程序 BM25 插件的 grep / search / hybrid，共四组。
- 每题每组重复三次，每次 180 秒预算，共 **600 次答题**。
- 最多另有 600 次语义判分；50 条固定查询的准备最多 150 次格式尝试。
- 两层分开：固定查询每题只 Search 一次；Agent 阶段自由多轮探索。

**600 次是已定义的正式工作量，不是已完成成绩。** 本轮已完成小规模端到端验证，正式运行计划保存到 `data/bcp-main-50-plan-20261013/`，尚未开始执行。既有 20 题的 180 次成绩继续保留，不拼到这批 50 题中。

## 本轮实际验证

使用已有的 2 题、55 篇文档接入集，每组一次、120 秒预算，共执行 10 次答题。输出位于 `data/bcp-main-smoke-20261013-v3/`。

| 配置 | 判对 / 判错 / 未判 | 平均工具调用 | 耗时 P50 |
|---|---|---:|---:|
| 无知识库 | 0 / 2 / 0 | 0 | 15.27 秒 |
| 程序 BM25 · grep | 1 / 0 / 1 | 13 | 120.32 秒 |
| 程序 BM25 · search | 2 / 0 / 0 | 8 | 90.36 秒 |
| 程序 BM25 · hybrid | 1 / 0 / 1 | 10 | 91.73 秒 |
| 内置 BM25 · search | 2 / 0 / 0 | 8 | 90.71 秒 |

共 6 次判对、2 次判错、2 次执行失败未判。两次未判保留在分母中，没有补跑替换。这里的“判对”来自 Flash 语义判分；输出 JSON 格式检查和精确匹配代理另列，不混为答案正确率。只有两题，这些数字用于验证链路，不能据此认定 Search 的稳定正确率为 100%。

固定查询共生成 2 条，使用 3 次格式尝试；其中一次格式失败已留存。两个插件复用相同查询和 qrels，4 次单次检索均成功，均得到 Recall@10=0.250、nDCG@10=0.315。两者都是 BM25 实现，这次同分不代表不同检索算法没有差异。单次查询召回也不能与 Agent 多轮累计证据召回直接比较。

同时核验：

- 无知识库组的真实模型请求工具目录为 `[]`，工具调用为 0。
- 新 50 题与旧 20 题开发集 ID 无交集；两个插件查询和标签指纹一致。
- 已完成实验执行 `--resume --execute` 后校验并跳过全部阶段，没有重新调用模型。
- 9 个相关测试文件共 **73 项通过**，覆盖原读写、数据导入、检索、工作流、负载评测和新增主基准能力。

前两次查询准备分别暴露了错误套用答题格式校验、模型返回不完整 JSON 的问题；已修正独立查询校验并加入最多三次的格式准备机制。失败目录 `data/bcp-main-smoke-20261013/` 和 `data/bcp-main-smoke-20261013-v2/` 原样保留，均未进入正式 Agent 答题阶段。

## 运行和产物

```powershell
# 只创建可审查计划，不调用模型
python -m benchmarks.browsecomp.campaign --dataset data/bcp-main-50-20261013 --output data/bcp-main-50-plan-20261013

# 输入和源码保持一致时开始执行该计划
python -m benchmarks.browsecomp.campaign --dataset data/bcp-main-50-20261013 --output data/bcp-main-50-plan-20261013 --resume --execute
```

主目录保存 `plan.json`、`status.json`、`source-snapshot/`；执行完成后增加统一 `report.md` 和 `metrics.json`。

```text
queries/                 # 问题生成的固定查询、标签和生成轨迹
retrieval-program-bm25/   # 单次检索指标
control/                 # 无知识库答题和判分
program-bm25/            # grep/search/hybrid 答题、判分及逐任务轨迹
```

机器评分记录与人工复核分开。题目、答案、正文、模型轨迹只在 Git 忽略的本地 data 目录；源码仓库提交代码、配置、合成单元测试与不含原题答案的汇总。

已从旧 20 题基线实际导出 `data/bcp-review-20261013/review.csv`：3 个机器判错答复，加每组 3 个随机机器判对答复，共 12 条；6 次执行失败保留在运行报告中，不伪造待判答案。当前人工判定栏全部留空。

## 边界

1. 仍为缩小语料、单分片抽样的内部基准；全量语料需要更大容量索引，不能与官方完整榜单比较。
2. 独立检索是最多 10 个片段内的文档去重指标，不是文档 Top-100/1000。查询由无工具模型根据问题生成，不是官方原题原样直接搜索。跨批次比较时也必须复用同一查询 CSV 和 qrels，并校验指纹，不能重新生成后直接比高低。
3. 同模型判分偏差明确保留；人工抽检入口已实现，尚未有人回填时不能说“已人工验证”。
4. 小规模接入测试不能证明稳定正确率；bootstrap 区间在样本少或同分时会退化，不作为显著性结论。
5. 当前续跑以完整阶段为边界，半个阶段不会静默覆盖或选题补跑；尚未实现逐题断点续跑。大规模运行前应保持环境稳定并留存中断记录。
6. 插件按配置顺序运行，远端模型负载变化仍可能影响延迟；实际硬件和远端模型版本并未达到完全可控的实验环境。

实现入口与参数见 [BrowseComp-Plus README](../../benchmarks/browsecomp/README.md)。
