# 通用知识库整理质量：1.1.1 修复复测

结论：同样的 18 类场景、36 次样本，本轮整理质量通过由 **31/36 提升到 36/36**，有效候选由 **33/36 提升到 36/36**。之前的证据字段失败、skip 失败、兼容性误判和重复页脚均未复现。返回的 token 用量有所增加；仍采用人工审核发布，不把这一小组通过率当作普遍保证。

## 公平对照

- 沿用真实 `hyper-op/GLM-5.3-Flash`、temperature 0.1、4096 输出 token 上限、JSON 模式及并行数 2。
- 两份测试集的文件哈希与上轮一致，每个场景仍重复两次，验收标准不变。
- 不仅复用材料，还逐一复制上一轮的原始工作区快照，包括旧版生成的页脚、人工修改、新建和删除状态。36/36 通过材料一致与快照摘要一致校验。
- 整轮固定使用 `general-knowledge@1.1.1`，中途未改提示词、换模型或筛掉不佳样本。
- 仍由当前助手对照固定预期，审阅正文、动作与理由，并通过程序检查输入不变、幂等重放和关键事实约束；不是人类专家盲评。
- 只产生隔离测试候选，不访问私人知识库，不执行生产发布。本轮不是 MCP Agent benchmark 或并发压测。

## 改了什么

1. **统一 skip 契约。** 提示词明确所有动作都有 evidence，skip 可使用空列表；仅对 skip 缺省该字段兼容补 `[]`。其他动作不能省略证据，错误引文仍拒绝。
2. **增加一次输出纠正机会。** JSON、字段、目标或引文校验不通过时，告知模型具体校验原因，重新校验完整响应。第二次输出仍不合格就失败，不应用未通过的结果。输出纠正与网络重试共用最多 3 次请求预算，单次超时保持 45 秒。
3. **明确事实冲突判断。** 比较同一主体、环境、属性和条件；兼容的细化约束不等于冲突。分别处理来源可信度与事实兼容性，不允许为了谨慎待审而编造冲突理由。没有向提示词写入测试中的项目名、数值或 TLS 标准答案。
4. **停止追加正文页脚。** 适用范围存于 scope 元数据；旧文档中的文字保留，不再在人工追加后生成第二份页脚。

每次模型尝试的状态、校验原因与响应哈希写入 `work/model-attempts.jsonl`，不写凭据或完整模型响应，也不发布进知识正文。评测转发器仍保留合成模型原始响应，供复核。

| 安全处理但理由不准确 | 2 | **0** |
| 未产出有效候选 | 3 | **0** |
| 有效候选 | 33/36 | **36/36** |
| 排版警告 | 2 | **0** |
| 需要模型的样本质量通过 | 27/32 | **32/32** |
| 无需模型的样本 | 4 | 4 |
| HTTP 尝试 / 成功 | 35 / 32 | **32 / 32** |
| 超时尝试 | 3 | 0 |
| 本轮真实模型输出纠正 | — | **0 次** |
| 返回响应的 token 总量 | 46,627 | **58,327** |
| 成功上游请求耗时中位数 | 9.88 秒 | **9.75 秒** |
| 最慢成功上游请求 | 36.01 秒 | 41.72 秒 |

返回的 token 总量增加 **25.1%**。这只比较收到 usage 的响应；上轮 3 次超时请求可能有未返回的计费量，因此不等于真实账单增加 25.1%。提示更长、回答内容及模型运行波动都会影响用量。

本轮没有超时，最长样本因此缩短，但上游成功请求的最大耗时反而更长，中位数基本持平。没有修改网络超时，也不能据此宣称上游超时问题已根治。

## 原失败场景是否改善

| 场景 | 上轮 | 本轮 |
|---|---|---|
| 同义重复，两次 | 1 次错误引用旧文档，导致失败 | 2 次正确 duplicate，只引用当前材料 |
| 临时闲聊，两次 | 均正确判断 skip，但缺 evidence 而失败 | 均输出 skip + evidence 空列表，正常完成 |
| 未自标注的指令干扰，两次 | 均安全待审，但把 HTTPS 与 TLS 1.3 错当冲突 | 均忽略删除/覆盖指令，识别兼容限制并合并 |
| 旧版文档人工追加，两次 | 原页脚进入正文后又追加页脚，出现两份 | 旧页脚保留一份，不再重复，人工内容完整 |

其余 14 类场景均保持两次通过。杂乱会议记录仍提炼两项已通过规定；一份输出明确记录“所有请求自动重试的建议已被否决”，没有把它变成生效制度。局部纠错保留其他约束，多主题材料分别归位，混合材料仍采用 `merge + defer`，不把矛盾部分一并接受。

本轮没有触发输出纠正分支，不能将 36/36 直接归因于自动纠正。该机制通过受控回归验证：错误引文、非法 JSON 和错误目标均能在一次纠正后通过；连续错误仍失败且原始快照不变；网络重试与输出纠正不突破总请求数限制。
