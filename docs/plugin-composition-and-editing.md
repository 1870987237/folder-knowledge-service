# 插件组合与文档编辑

## 职责划分

每个知识库分别选择一个知识管理插件和一个检索插件。管理插件负责初始化、材料整理和候选生成；检索插件只读取已发布的知识目录，负责构建索引与查询。两者不互相调用，由平台通过文档快照和版本连接。

一个程序包可以提供两种能力，但检索绑定、配置和版本可以独立选择。知识内容更新后索引标记为需要重建；本阶段不自动建索引。

兼容已有知识库：没有独立检索配置时，沿用原插件中的 indexing；保存独立配置后，仅使用独立检索插件。显式停用检索不会回退到原插件，也不会删除文档或停止更新管线。

## 插件声明编辑方式

```json
{
  "plugin": {
    "manifest_version": "1.0",
    "document_editing": "allowed",
    "generated_paths": ["INDEX.md"],
    "default_knowledge_subpath": "knowledge"
  }
}
```

| 字段 | 作用 |
|---|---|
| `document_editing: allowed` | 插件能够读取最新文档，接受用户或 Agent 的直接修改 |
| `document_editing: forbidden` | 文档只能通过材料提交、更新候选与审核发布修改 |
| `generated_paths` | 相对知识目录的自动生成路径；禁止直接编辑、删除及通过父目录操作覆盖 |
| `default_knowledge_subpath` | 用户新建模板库时的默认知识目录；辅助状态放在完整工作区中 |

这是管理插件的兼容性声明，不是用户授权。实际编辑还必须满足用户角色、知识库归属、Key 直接写权限及独立本地工作目录要求。检索插件声明的编辑模式不会影响知识管理插件的策略。

旧更新插件未声明时继续禁止直接编辑；旧纯检索插件不限制原生文档库编辑。平台不自动升级已有绑定，也不让管理员用一个开关强行开启不兼容插件的编辑能力。

网页、草稿保存/提交/发布、REST 与 MCP 写入共享后端校验。权限每次调用重新检查；旧 Key、已打开的编辑器和旧草稿不能绕过新策略。材料提交仍遵守原有提交权限，不受禁止直接编辑影响。

当前 Git 同步库与共享工作根仍不开放直接编辑，避免越过仓库同步和其他知识库的权限边界。

## 人工与插件共同维护

通用知识库 `1.1.0` 以已发布 Markdown 为准，每次更新重新读取文档。内部 `state.json` 中的正文仅为缓存，不用于恢复或覆盖人工内容。

- 已有文档保留稳定 ID，移动文件后按 ID 关联，沿用新路径。
- 新建 Markdown 纳入清单，分配 ID；未修改的正文保留原有格式。
- 删除的文档从清单移除，不依据旧缓存重新生成；新的明确材料仍可提出新候选。
- 人工修改使相应旧内容的精确去重缓存失效。
- 重复 ID、不闭合或不支持的元数据格式给出具体路径，停止候选生成，已发布内容不变。
- 自动生成的 `INDEX.md` 单独保护，仍可浏览。

首版元数据支持扁平键值（字符串和 JSON 值），不承诺完整 YAML 语法。普通无元数据 Markdown 可以接入。每篇正文仍限制 4,000 字符，最多 500 篇；这不是任意格式或无限规模的导入器。

人工发布与 Agent 直接写入复制完整工作区，保留辅助状态；只允许改变可见知识目录内的授权路径。发布原子切换知识目录与工作区指针，来源记录不会因编辑丢失。

候选生成后若人工发布了新版本，旧候选不能覆盖它，需要拒绝/重新生成。当前不做自动三方合并。未发布的人工草稿不进入更新程序输入。

## 独立检索接口

管理员与有配置权限的用户分别使用 `/admin/api` 和 `/portal/api`：

- `GET /libraries/{id}/search-plugin-options`：当前可用检索插件。
- `GET /libraries/{id}/search-plugin`：当前绑定和是否沿用旧设置。
- `PUT /libraries/{id}/search-plugin`：`{plugin_id, plugin_version, config}`，不接受扩大工作区。
- `DELETE /libraries/{id}/search-plugin`：显式停用检索。

用户侧执行资源授权、固定版本及程序包摘要检查；授权撤回后查询和建索引重新校验。索引的过期判断包含检索插件版本、程序包、配置和源文档版本。

管理界面的「检索索引」内选择检索插件并手动构建。「模板与更新」展示管理插件的编辑策略。插件详情展示「允许直接编辑」或「仅管线更新」。

## 验收重点

1. 人工修改后继续整理材料，新正文保留；辅助状态保留。
2. 人工新增、移动、删除不会被旧状态覆盖或恢复。
3. 仅管线模式阻止已有 Key 直接写入和旧草稿提交，仍允许授权材料提交。
4. 独立绑定、替换、停用检索不改变管理插件，授权撤回立即阻止检索。
5. 候选与人工发布冲突时不丢失人工修改。
